# 16 个未实现模块的核实收口设计

## 背景

用户在 2026-11-17 问：当前这个项目的功能模块是否全实现。对账结论：没有全实现。差距表的 21 个模块中，3 个是「已实现」，16 个是「未实现」，2 个是「无广约束」。112 个契约端点与 36 张表已落地。

随后用户要求把 16 个未实现模块都实现。核实代码与 git 历史后，我们发现 16 个模块中大部分已有代码和验证证据；「未实现」是 2026-11-15 的旧快照。本设计只处理三类真实缺口：文档漂移、本地测试后端联调、外部凭证边界。

## 目标

本轮完成三件事：

1. 把差距表、页面对照表和接口实现对照表中过期的模块状态改为当前状态，并附证据。
2. 用本地 Ktor 测试后端验证核心业务端点的明文 JSON 契约、统一响应信封、错误码与退避重试。
3. 如实记录不实现的外部项：真实运营商一键登录、个推与 4 厂商推送、真实支付商户资质。

## 非目标

本轮不做以下工作：

- 不按 16 个模块从零重写代码。
- 不接入真实运营商 SDK、个推或厂商推送通道。
- 不接入支付渠道、VIP 区分或广告 SDK。
- 不复制原 App 的资源、协议文本或私有加密算法。
- 不追求全部 112 个端点的本地后端实现；只做核心业务端点。

## 工作包

### W1 文档核实与订正

修改 `docs/功能差距表.md` §1 状态列与缺口列，按核实结论写入当前状态和证据。修改 `docs/功能页面对照.md`、`docs/接口实现对照表.md` 与实施计划，使四份文档一致。

文档必须区分三类词：

- 「已实现」：代码存在，测试或真机记录存在。
- 「待证据」：代码存在，验证记录缺失。
- 「边界」：按设计不实现真实外部服务。

### W2 本地 Ktor 测试后端

新增一个仅用于 JVM 测试的本地 Ktor 后端。后端绑定回环地址，使用随机端口，不进入生产包。后端实现核心明文 JSON 契约：

| 端点 | 验证内容 |
| --- | --- |
| `Account/LoginByDevice` | 统一响应信封、`data` 字段、错误码 |
| `Bills/Add`、`Bills/Update`、`Bills/GetList` | 字段名、整数分金额、幂等键 `client_id` |
| `Cate/GetList` | 分类列表字段 |
| `Budget/GetList` | 预算字段 |
| `Behavior/Add` | 上报队列排空 |

测试覆盖四件事：

1. 成功响应解析为业务对象。
2. 业务错误码不崩溃，调用方拿到明确错误。
3. 网络中断时 `SyncEngine` 保留队列并按退避重试。
4. `sync_base_url` 为空时不发请求，UI 不阻塞。

### W3 验证与提交

按顺序跑以下验证：

1. `./gradlew :shared:jvmTest`
2. `./gradlew :app:assembleDebug`
3. `./gradlew checkAdDeps`
4. `git diff --check`

验证通过后更新 `docs/superpowers/plans/2026-11-11-kmp-full-replica-plan.md`：写提交号、测试结果和剩余边界。最后 commit 并 push。

## 风险与对策

**警告：** 本地测试后端只用于 JVM 测试。不得把测试基地址写进 App 默认值，也不得把真实账号数据发往测试后端。

**注意：** 文档状态更正不等于新增功能。待证据模块只改验证状态，不标记为已实现。

**注意：** 本轮不接真实外部凭证。边界项保持「边界」状态，不用沙箱冒充真实服务。
