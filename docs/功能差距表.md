# KMP 全量复刻功能差距表

本表登记 KMP 实现状态（2026-11-12 对账）。状态列只使用「已实现」「未实现」「无广约束」「待证据」四个值。「已实现」表示 KMP 有对应代码，且计划中的验证已完成；「未实现」表示未达到该行的完整口径（已有局部代码不计为完成，已有内容写在「现状」/「缺口」列里）；「待证据」表示现有文档不足以确定验收条件；「无广约束」表示用户指定不实现广告功能。

> **对账口径**：本文档记录 `origin/master` 加三个先于本 PR 合并的分支状态——PR #3 `fix/network-contract`（网络契约接线、`sync_base_url` 隐私门禁、请求头、GET 修正、unwrap、动态 `@Url`、逐笔 `Bills/Update`）、PR #2 `fix/db-migration-v3`（`1.sqm`/`2.sqm` 重排与迁移回归）、PR `fix/interaction-discipline`（规则删除二次确认、待确认队列批量通过/忽略/修改、真实清空本机数据、入口页三态主题、下线 `autoConfirm`）。原先使用的「部分实现」按上文规则统一映射为「未实现」，已落地的代码保留在「现状」列，不因状态改名而抹掉。
>
> 下文凡提到「112 端点」，指 `spec/endpoints.json` 的 112 个注解路径（111 个唯一路径，9 GET / 103 POST）；2 个动态 `@Url` 单独计数。`src/`（Web）与 `android-shell/`（WebView 壳）是规格参考，不计入 KMP 实现状态。

`01` 指 `D:\workspace\recordAccount\01-功能点全量清单.md`，`02` 指 `D:\workspace\recordAccount\02-业务架构.md`。`spec/endpoints.json` 是 112 个注解路径 + 2 个动态 `@Url`（`dynamic: true` 条目）的全量权威清单。

## 6. 更新规则

1. 每个切片完成后，执行者应更新本表对应模块、端点、页面、表和门禁的状态。
2. 执行者应把「已实现」对应的代码路径写进「KMP 实现位置」列。
3. 执行者应在实施计划记录提交号、构建结果和真机结果。
4. 如果代码删除或功能回退，执行者应把状态改回「未实现」。
5. 如果想把「待证据」改成「已实现」，执行者应先补验证命令与输出记录。
6. 状态列只使用「已实现」「未实现」「无广约束」「待证据」；局部已有的代码写进「现状」/「缺口」列，不新增第五种状态值。
7. S8 完成前，本表不得出现空白状态列。
